# 合伙有序 · 合作执行台

**v1.1.0 可运行源码，面向小型合伙团队。** 将合作计划、阶段资金、分工、采购会签、执行凭证、审计记录和有依据的AI风险分析放在同一个 Web 中。正式部署路线只有 **Cloudflare Workers + D1 + 私有 R2**；电脑和手机浏览器均有适配。

不是记事本，也不是实际付款系统。每笔采购默认由**全体已加入的合伙人**明确批准，不开放“超时视为同意”或管理员强行放行的入口。

## 仓库与界面预览

项目仓库：<https://github.com/lanchenglin/hzjc>。

本仓库包含运行源码、数据库迁移、自动化测试和部署文档。静态演示截图保留在原始交付 ZIP 的 `docs/previews/` 中，不作为运行依赖；启动本地服务即可查看电脑与手机界面。

## 本版已经实现

| 模块 | 实现范围 |
|---|---|
| 合作项目 | 多项目、邀请成员、合伙人/执行成员/只读成员、分配比例、合作约定 |
| 阶段计划 | 目标、预算、验收标准、截止日期、基准计划全员确认、阶段开放和关闭审批 |
| 分工任务 | 指定负责人和不同的验收人、交付成果、进度/阻碍、交付验收、延期/换人走共同决策 |
| 采购会签 | 商品明细、报价依据、供应商和收款对象、风险与退出方案；冻结会签名单；已阅与同意分开 |
| 防绕过 | 全员会签、预算及资金检查在后端执行；采购关键内容变更生成新版本，旧签名失效；不允许自行移除反对者 |
| 采购执行 | 登记订单、分次登记付款、剩余批准金额、不同成员复核账目、指定不同验收人、分批收货 |
| 财务与结算 | 内部收支、出资/借款、应收应付、手动销售成本、共同对账、按批准比例结算、登记分配付款 |
| 真实异常 | 已发生但未经批准的支出仍可登记并告警；任一合伙人可暂停新增采购，恢复须全员同意 |
| 留痕和导出 | 审计哈希链、数据库禁止直接更新/删除审计行、JSON 项目导出、CSV 账目、私有附件 |
| 通知 | 站内个人待办、企业微信群机器人、阿里云关键异常短信、定时到期提醒、失败/不确定状态 |

第一版固定采用 `all_partners` 全体合伙人会签，不实现多数票、任意2人同意、代理签名等降低约束的方式。每项目2–30位合伙人，总成员最多40人。

## v1.1 新增 AI 分析

项目页面的 **AI分析** 提供项目合理性、采购风险、阶段复盘三个入口；程序计算金额和规则，AI解释风险，来源快照、历史报告、失败记录、费用估算及人工任务草稿均可追踪。

**AI默认关闭。** 部署者配置服务端密钥/模型/真实人民币费率后，仍需每个项目全体合伙人确认数据范围、模型、额度和触发规则。AI不能改预算/账目、没有审批票，报告不替代实际付款复核。

- 使用与API配置：[`docs/AI_ANALYSIS.md`](docs/AI_ANALYSIS.md)
- 已测/未测边界：[`docs/ACCEPTANCE_AI.md`](docs/ACCEPTANCE_AI.md)
- 从v1.0升级：先备份，再按 [`docs/HERMES_DEPLOY.md`](docs/HERMES_DEPLOY.md) 执行新增迁移 `0002_ai_analysis.sql`；不改写或删除旧数据。

报告只分析系统已录入资料，不联网查市场，不读取附件原文件。模型API必须另行配置；本次没有调用真实收费模型或部署云端。

## 立即本地体验（不需要 Cloudflare 账号）

需要 **Node.js 22.16.0 或更高版本**，必须支持内置 `node:sqlite`。推荐在 WSL/Linux 运行。

```bash
git clone https://github.com/lanchenglin/hzjc.git
cd hzjc
npm run dev
```

本地服务器地址：

```text
http://localhost:8787
```

核心运行不依赖 npm 包，**这个本地入口无需先执行 npm install**。首次启动自动生成 `.dev.vars`，用其中的 `BOOTSTRAP_TOKEN` 在网页初始化自己的账号。新密码12–128字符。不要把初始化口令发给合作成员；成员使用各自的邀请链接与密码。

本地数据保存在 `.local/`，重启不会丢失。该入口是本项目的 Node/SQLite 开发适配器，**不是生产 Node 部署方案，也不是 Cloudflare 官方模拟器**。

### 可选：先加载三人合作演示

必须在尚未初始化的空白本地实例中执行；另开一个终端：

```bash
npm run demo
```

脚本创建三名虚构合伙人、三阶段计划、出资、两张采购单、任务与已复核收入。账号及随机密码仅写入 `.local/demo-accounts.json`。演示脚本拒绝非 localhost 地址，也拒绝已有初始化数据的实例，避免污染真实账目。

先做演示、或先初始化真实本地账号，二选一。切换时使用新的解压目录，不要直接删除可能有用的数据。

## 第一次建立真实合作项目

1. 初始化自己的账号并创建项目，填写总预算、最低保留资金、阶段目标和合作约定。
2. 添加其他合伙人，分别生成并私下发送邀请链接。新增成员自己设置密码。邀请有效期7天，重新生成会使未使用的旧链接失效。
3. 成员全部加入后调整分配比例使合计100%，提交“合作基准计划”，每个合伙人分别确认。创建人也必须明确表态。
4. 登记实际已到位的出资及依据，由不同合伙人复核。没有核实资金不能仅凭预算发起大额采购。
5. 建立分工任务。采购申请在当前开放阶段提交，每人明确同意当前版本后再交给执行人。
6. 线下实际付款前核对有效批准内容，付款后登记真实流水，另一人复核。收货由指定的不同验收人完成。
7. 按期共同对账，结算也需全员确认。对账和利润均来自内部登记，并非银行同步或法定财务报表。

详细操作、审批边界、财务口径见 `docs/USER_GUIDE.md`。

## 测试

```bash
npm run check
npm test
```

后端测试在真实 Worker 源码上调用接口，数据库使用本地 SQLite 事务适配；不等同于已在真实 Workers/D1/R2 上验证。v1.1全量 **92项后端测试通过（原61项+新增31项）**，模型响应由测试替身提供，未发送真实收费请求。新增AI界面 **11项离线Chromium检查通过**（含360/390px手机布局），不是浏览器到后端的完整在线联调。历史v1.0测试报告仍保留，新增报告位于 `docs/test-results/`。

官方运行时与云端部署需要安装开发工具：

```bash
npm install
npm run db:local
npm run dev:workers
```

执行前按部署文档设置绑定。首次安装应保存生成的 `package-lock.json`；后续使用 `npm ci`。本次交付环境不能连接 npm 注册表，因此没有伪造 lockfile，也没有声称 Wrangler dry-run 已通过。

## 必须理解的边界

**源码完成不等于已经上线。** 本次未连接你的 Cloudflare 账号，没有创建云资源，没有配置域名，没有发出真实短信或企业微信消息。GitHub 中的源码不代表应用已经上线。

这个应用不能阻止他人绕过网页使用银行卡/微信付款，不能识别所有假凭证，也不能证明两个账号一定是两名不同自然人。请让各合伙人自己保管账号，并落实实际资金复核。审计链不等同于第三方存证或独立审计。
