## v1.5.0 · 出资方不盯细节，但不再等钱花完才知道偏差

新增 **出资人总览、简短汇报与成果、计划变更对比、阶段独立验收衔接、追加投入与个人分担、异常处理闭环**。原业务总览和其他功能保留。

升级后先在项目“出资人总览 → 监督规则”选择汇报负责人、另一位验收人、汇报/对账周期及可选限制，由全体合伙人确认后生效；旧项目不自动启用新限制。

“已阅、批准变更、个人出资承诺、实际到账、独立复核”分别记录。没有修改密码/MFA/AI Key存储；AI配置不重复验证的现有行为保持。本版未部署用户生产站点。

完整用法与限制：[`docs/SUPERVISION_V1_5.md`](docs/SUPERVISION_V1_5.md)。实际测试与未验证范围：[`docs/ACCEPTANCE_V1_5.md`](docs/ACCEPTANCE_V1_5.md)。从已完成0001–0005迁移的版本升级，无新增数据库迁移。


**v1.4.0 可运行源码，面向小型合伙团队。** 将合作计划、阶段资金、分工、采购会签、执行凭证、审计记录和有依据的AI风险分析放在同一个 Web 中。正式部署路线只有 **Cloudflare Workers + D1 + 私有 R2**；电脑和手机浏览器均有适配。

不是记事本，也不是实际付款系统。每笔采购默认由**全体已加入的合伙人**明确批准，不开放“超时视为同意”或管理员强行放行的入口。

## v1.4.0：简单配置、通用分析与小额分级

AI配置只需URL、Model、Key及必要协议/启停，不再填token单价或可见输出配额。项目情况用一段话描述，中视频、AI漫剧、软件或非盈利项目都适用，不要求客户和销量。内置提示词只读可查，可选补充偏好。

支出可用「快速支出申请」：买什么、承诺总额、简单用途、商家/收款对象；分工和日期提供建议值并可展开核对。默认建议500元阈值，等于或低于的普通支出不自动调用AI；超额或关联累计异常按已批准规则分析。手动分析任何金额均可，原全员会签和预算约束不变。

先应用 `0005_lightweight_ai.sql`，旧站点保留全部账号、密钥、MFA和历史记录；每个项目重新确认新的AI规则后才恢复外部发送。后台只记录调用与用量，不承诺免费或无限输出；明确长度中断最多补齐一次，最终仍须结构/引用校验。详情见 [AI使用说明](docs/AI_ANALYSIS.md)、[升级步骤](docs/HERMES_DEPLOY.md)、[v1.4验收](docs/ACCEPTANCE_V1_4.md)。

## v1.1 新增 AI 分析

## 立即本地体验（不需要 Cloudflare 账号）

需要 **Node.js 22.16.0 或更高版本**，必须支持内置 `node:sqlite`。推荐在 WSL/Linux 运行。

```bash
git clone https://github.com/lanchenglin/hhyx.git
cd hhyx
npm run dev
```

本地服务器地址：

```text
http://localhost:8787
```

核心运行不依赖 npm 包，**这个本地入口无需先执行 npm install**。首次启动自动生成 `.dev.vars`，用其中的 `BOOTSTRAP_TOKEN` 在网页初始化自己的账号。新密码12–128字符。不要把初始化口令发给合作成员；成员使用各自的邀请链接与密码。

本地数据保存在 `.local/`，重启不会丢失。该入口是本项目的 Node/SQLite 开发适配器，**不是生产 Node 部署方案，也不是 Cloudflare 官方模拟器**。

### 可选：先加载三人合作演示

必须在尚未初始化的空白本地实例中执行；另开一个终端：

```bash
npm run demo
```

脚本创建三名虚构合伙人、三阶段计划、出资、两张采购单、任务与已复核收入。账号及随机密码仅写入 `.local/demo-accounts.json`。演示脚本拒绝非 localhost 地址，也拒绝已有初始化数据的实例，避免污染真实账目。

先做演示、或先初始化真实本地账号，二选一。切换时使用新的解压目录，不要直接删除可能有用的数据。

## 第一次建立真实合作项目

1. 初始化自己的账号并创建项目，填写总预算、最低保留资金、阶段目标和合作约定。
2. 添加其他合伙人，分别生成并私下发送邀请链接。新增成员自己设置密码。邀请有效期7天，重新生成会使未使用的旧链接失效。
3. 成员全部加入后调整分配比例使合计100%，提交“合作基准计划”，每个合伙人分别确认。创建人也必须明确表态。
4. 登记实际已到位的出资及依据，由不同合伙人复核。没有核实资金不能仅凭预算发起大额采购。
5. 建立分工任务。采购申请在当前开放阶段提交，每人明确同意当前版本后再交给执行人。
6. 线下实际付款前核对有效批准内容，付款后登记真实流水，另一人复核。收货由指定的不同验收人完成。
7. 按期共同对账，结算也需全员确认。对账和利润均来自内部登记，并非银行同步或法定财务报表。

详细操作、审批边界、财务口径见 `docs/USER_GUIDE.md`。

## 必须理解的边界

**源码完成不等于已经上线。** 本次未连接你的 Cloudflare 账号，没有创建云资源，没有配置域名，没有发出真实短信或企业微信消息。GitHub 中的源码不代表应用已经上线。

这个应用不能阻止他人绕过网页使用银行卡/微信付款，不能识别所有假凭证，也不能证明两个账号一定是两名不同自然人。请让各合伙人自己保管账号，并落实实际资金复核。审计链不等同于第三方存证或独立审计。
