# 通知配置与故障处理

## 实现现状

站内通知已经可用，不需要外部服务。企业微信内部群机器人与阿里云国内短信接入代码已经实现，自动化测试用模拟服务商响应验证；本次交付没有真实渠道密钥，**没有发送真实消息，也没有做真实送达验证**。

默认 D1 outbox + 每10分钟 Cron。提交业务后会尝试即时处理少量通知；发送失败会保留状态，不回滚已完成的采购/审计操作。

到期提醒以 `TZ=Asia/Shanghai` 为业务日期，任务提前1天/逾期提醒、未完成采购会签、待共同决策按日去重。每轮扫描最多5个项目，每项目最多40条个人提醒，并保留项目和条目游标，后续 Cron 继续处理。大量项目会增加提醒延迟，不承诺实时或每条精确到分钟；上线需监测队列积压。

## 企业微信内部群机器人

不是普通个人微信群。由用户在合适的企业微信内部项目群添加机器人，取得 Webhook，所有群成员应有项目知情权限。不要向外部群或无关群测试发送项目名称。

在项目“通知中心 → 配置企业微信”录入，需创建人重新验证密码。服务端仅允许企业微信官方 HTTPS Webhook 主机与指定路径，地址使用 `CONFIG_ENCRYPTION_KEY` 加密保存；浏览器读取配置时不会返回秘密地址。

通知默认只含项目名、事项标题和登录入口，不附上收款账号、报价和凭证。消息正文仍可能敏感，因此需自行核对群成员。合伙人可以查看渠道配置状态和发送记录。

“发送测试通知”会真实调用已配置渠道。测试前取得许可。当前不自动点名群成员，也没有企业微信账号与站内账号的自动映射；个体待办以站内记录为准。

## 阿里云短信（可选）

正式开通需要用户自己的服务资质、审核通过的签名和通知模板。以提供商当时的审核要求为准，不能只准备AccessKey就保证发得出去。

服务端 Secret：

```text
ALIYUN_ACCESS_KEY_ID
ALIYUN_ACCESS_KEY_SECRET
ALIYUN_SMS_SIGN_NAME
ALIYUN_SMS_TEMPLATE_CODE
```

使用短信所需最小权限的凭据，不使用主账号长期密钥。模板固定传入两个变量 `project` 和 `title`，示例文字如下；实际以审核通过的内容为准：

```text
项目${project}有重要事项：${title}，请登录合作系统核查。
```

短信目前只发**critical级关键异常**，例如紧急暂停、未批准支出等，不会把每条日常进度都发成收费短信。接收人必须在个人设置中填写本人中国大陆手机号并主动开启短信。初版不提供验证码校验手机号归属，所以应由本人确认号码、管理员控制服务商配额，不能允许代填任意号码群发。

实现使用阿里云RPC签名的SendSms接口；自动化测试包含官方签名样例。短信发送结果保存 `BizId/RequestId`，在渠道接口可查，不实现服务商状态查询/回执回调自动同步。真实测试需人工查看服务商控制台和收件设备。

## 状态不是同一个意思

| 状态 | 含义 |
|---|---|
| pending / retry | 等待发送或有限重试 |
| sending | 发送进程持有短期租约 |
| accepted | 服务商接口接受；不代表已送达、更不代表阅读 |
| not_configured | 未开通/未配置；没有伪装成成功 |
| disabled | 接收人未开启或已不在项目中 |
| failed | 明确失败，需要修正原因 |
| uncertain | 短信超时/5xx/发送进程中断，可能已经发出，结果不确定 |

企业微信临时失败/限流退避重试，最多5次。短信没有应用可依赖的发送幂等保证，超时和5xx进入 uncertain，不自动盲目重发，以免重复收费。人工重发前需明确确认已检查服务商记录并接受可能重复；已被服务商接受的消息不能在普通重试入口重复发送。

读取站内通知不等于点击采购的“我已阅读当前版本”；采购已阅也不等于明确同意；同意不等于已执行。

## 维护

若没有收到提醒，依次检查：Cron是否触发、outbox是否积压、渠道是否配置、当前状态和错误、手机号是否主动启用、企业微信频率限制、短信服务商余额/签名/模板/回执。不要直接把全部 uncertain 批量改回pending。

默认不配置 Queue；增加队列步骤见部署文档。队列提升投递调度能力，不能让服务商响应变成真实阅读证明。
