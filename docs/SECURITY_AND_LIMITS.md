# 安全、架构与第一版边界

> **v1.2.0更新：** 已加入系统管理员后台、归档/回收站、用户权限与网页AI配置。以下早期版本内容需结合 `ADMINISTRATION.md` 阅读；升级必须应用0003，不能只替换前端。旧密码保留，管理员不能代签，已发生业务不物理删除。

## 数据与并发设计

Worker 是唯一业务入口。D1 的 `projects.state` 保存一个项目的业务聚合；独立表保存账号、会话、访问索引、审计、操作幂等回执、邀请、附件目录与通知。R2 保存私有附件。

每次变更按项目 revision 做 compare-and-swap，在同一个 D1 batch 事务中写入项目新状态、预算/会签结果、审计、幂等回执与通知。发生冲突重新读取并校验，最多重试7次；仍冲突返回409，不悄悄放宽预算。每次数据库提交尝试使用独立 guard，防止相同逻辑幂等请求并发重放产生重复记录。

操作幂等键绑定用户、项目和请求内容；同一键提交不同内容返回409。初版保障项目 actions 的业务操作幂等；新建项目、生成邀请及文件上传不应视为通用可无限重放接口。网络异常后先查看结果，重新生成邀请会替换旧未使用链接，避免重复上传文件。

以一个聚合完成资金和会签原子校验，是小团队第一版的取舍，不是大企业高并发架构。

## 已实施的保护

- 账号仅通过初始化或有效邀请创建；没有开放注册和共享默认密码。邀请随机token只存hash，7天有效。
- 密码使用scrypt（N32768/r8/p3），12–128字符；会话12小时，cookie为HttpOnly/SameSite=Strict，HTTPS下Secure和__Host前缀。
- 写请求校验精确Origin和CSRF；重要操作5分钟内重新验证密码。登录、初始化和重新验证有数据库限频。
- 没有业务超级管理员通道。后端验证当前成员权限、冻结全员会签、当前版本与预算，不能只修改前端按钮绕过。
- 附件经过项目成员检查、私有R2、强制下载、不嗅探内容；最大10MB。拒绝HTML/SVG等主动内容类别；没有病毒扫描，也不能保证文件本身无恶意，请用安全阅读器。
- 内容输出转义、CSP、禁止iframe嵌套、CSV防公式注入。会话/密钥不放localStorage，前端的localStorage仅用于界面偏好。
- Webhook限定官方HTTPS主机并AES-GCM加密。任何加密都不保护已掌握服务端解密密钥的管理员。
- 审计表应用层只追加，数据库触发器拒绝UPDATE/DELETE；链记录修改前后状态hash。可导出校验，不能防御数据库管理员重写整条链。

## 明确没有实现

实际银行/微信支付限制或转账、税务/完整会计/自动库存成本、第三方审计、司法电子签章、自然人实名验证、MFA、邮箱验证、短信手机号验证码、自动密码找回、强制退伙仲裁、创建人转移、已下单订单完整修订与退货工作台、跨项目集中资金池、多币种、多数票或代理签名。

邮箱目前是账号标识，通过可信渠道转发邀请链接确认接收人，不等于系统验证邮箱所有权。不同账号不必然对应不同的人，实际合伙人需自行保管账号。禁止创建人掌握所有人的密码后自己全签。

遗失密码应由部署维护人核实身份并记录受控恢复处理；应用没有替人签名或以管理员恢复为由改写原批准人的界面。没有把高风险的自助重置入口做成不验证身份的捷径。

## 容量与保守限制

| 项目 | 第一版限制 |
|---|---|
| 单项目合伙人 | 2–30人，最多30人的上限在新增前检查 |
| 单项目有效成员 | 最多40人，含执行/只读成员 |
| 单项目阶段 | 1–30个 |
| 单张采购明细 | 1–50项；数量为正整数 |
| 单附件 | 最大10MB，私有文件 |
| 项目JSON聚合 | 上限约1.4MB，达到阈值拒绝继续扩大；不自动删除历史 |
| 网页一次完整审计导出 | 最多10,000条；更大用受控数据库备份 |
| 当前待共同决策 | 每项目一次只处理1项，避免规则互相覆盖 |
| 定时扫描 | 每10分钟最多5项目，每项目40条提醒，轮转游标 |

长期大量采购、商品行、凭证历史及任务更新会增加聚合大小。接近上限时先独立导出和备份，再按新的合作周期创建新项目；不要删旧审计扩容。更大业务量应迁移为规范化业务表/事务架构后再使用，不能把此版本宣传成无限容量。

真实Cloudflare平台还有CPU、D1查询次数和对象存储额度。正式部署需在目标账户验证，不能用本地测试推断免费计划一定可运行。尤其30–40成员的事务会产生较多独立记录，免费每次调用配额可能不足。限制详情以官方当前文档为准。

## 财务安全边界

现金余额和利润都是内部已录入事实的计算，不是银行同步。未复核收入不释放采购额度，未复核流出先扣减；已形成订单/分配的未付金额继续占用资金。数量与金额用整数避免常见浮点舍入问题。

虚假出资、漏记成本、错误验收和成员合谋仍可能导致错误决策。将“核实”按钮当作审计报告是不合适的。需要真实流水、原始凭证、双方核对和实际付款权限安排配合。

## 备份和恢复

D1导出包含账号hash、人员、财务和加密渠道信息，应加密离线保管。R2单独备份；保存加密密钥但与备份分开。网页JSON仅含项目和审计以及附件目录，不包含用户库、会话或真实附件字节，不是完整站点备份。

生产升级前做快照，恢复演练使用全新的测试库/桶，验证审计链和附件hash。不要直接覆盖生产库证明“能恢复”。切换APP_URL或轮换密钥前确认影响；加密密钥变化需重新设置渠道。

日志避免记录密码、邀请token、Webhook和供应商秘密。监测错误、预算冲突、异常支出、通知积压；不以错误重试为由绕过业务核验。

## AI分析补充边界（v1.1）

AI是只读建议服务，没有工具、采购票或数据库直接写权限。原金额计算、预算占用和全员会签仍在后端执行。模型建议只能经人工确认进入现有任务接口，不可自动改预算、分工、原计划或账目。

每项目启用、费用额度、数据接收方和自动触发必须全体合伙人确认；人数/配置变化导致旧授权失效。普通成员不能修改全局AI主机允许清单或密钥。手动调用限流并使用事务预占，运行任务原子领取，同输入缓存；未知计费保留预占，失败不自动重试。

发送输入按本项目字段白名单生成，屏蔽结构化身份/账户/凭证/秘密；自由文本仍须人工核查。没有完全防敏感信息泄露或提示注入的保证，第三方服务保留数据方式须由部署者核实。模型结果经过JSON/来源/短引用校验、HTML转义，但仍可能推断错误、偏见或遗漏事实；报告不是项目通过证明。

本版不做联网市场核查、附件全文/OCR、独立审计或自动银行对账。所有报告及失败记录向有效项目成员公开，不提供挑选性删除；最高数据库权限仍可以破坏约束，哈希链不是独立存证。

同一项目只允许一项排队/运行分析。输入上限80KB、100阶段/200任务/150采购/500账目，不静默截断；每项目最多1000条运行元数据并受原状态容量限制。UTC日期变化会使报告过期；这不是市场联网更新。调用时限20秒、租约60秒、Cron每10分钟每次取一任务，不能承诺高并发实时处理。不能把20秒失败自动重试成多笔账单。

费用根据服务端人民币费率估算，模型缓存、汇率和供应商特殊收费可能不符合估算；应用预算不是绝对账单上限。配置真实费率、使用供应商预算限制、核对账单；禁止以降低安全校验/零费率/清空失败记录来绕过额度。

云端性能、真实模型响应质量与最终使用环境尚需验收。具体已测项目见 `ACCEPTANCE_AI.md`。


## v1.3 新安全边界

TOTP/恢复码是新增第二因素，不替代密码或全员会签。管理员策略默认不强制，绑定后的账号仍强制第二步；恢复码不可查询明文。MFA与服务商密钥依赖原CONFIG_ENCRYPTION_KEY，备份另用独立BACKUP_ENCRYPTION_KEY，两者均须安全保管。

备份需要真实不同的D1/R2资源，不是换绑定名；恢复演练目标含敏感解密数据，不能公开。备份容量16MiB/每表10000行/1000附件/每附件10MiB，超限报错；没有自动留存删除或生产灾备切换。即使界面提示资源存在，也须核实实际私有权限、资源ID、配额和费用。

通知配置不能自动给全站项目扩散数据；群范围由管理员说明、项目负责人确认，短信需本人同意。继承授权随配置变化失效。失败记录不能通过重发抹掉。

负责人移交及退出净额是项目共同约定：实际付款仍在线下，清算不自动免除对第三人的责任。网站无法防止管理员控制他人密码、数据库最高权限者恶意操作，不能宣传为绝对防篡改/实名签名。详细约束和故障处理见OPERATIONS_V1_3.md。


## v1.4金额分级与受控补齐

小额免外部AI不是免全员会签；阈值变更也需全员批准。新scope与配置指纹会使旧AI授权失效，不能静默从收费预算授权切换到次数授权。只记录用量、不计算人民币账单不等于调用免费；服务商应设置独立额度。明确长度中断最多再发一次，逐次计数；身份/资料/授权变化停止后续发送，已发出请求不可撤回。源码内置提示词与本地校验不保证模型判断正确。
