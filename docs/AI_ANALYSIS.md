# AI 项目分析 · v1.1.0

> **v1.2.0更新：** 已加入系统管理员后台、归档/回收站、用户权限与网页AI配置。以下早期版本内容需结合 `ADMINISTRATION.md` 阅读；升级必须应用0003，不能只替换前端。旧密码保留，管理员不能代签，已发生业务不物理删除。

> 模型设置现在优先通过 **系统管理 → AI模型配置**。Key以配置根密钥加密保存，留空保留、不回显；环境变量为尚未后台保存时的兼容路径。配置（含Key轮换）更新后，各项目重新确认外部AI授权。

本模块已经接入项目系统，不是通用聊天框。三个入口是 **项目合理性分析、采购风险分析、阶段复盘**。AI没有采购审批票、没有付款工具，不得改预算、账目和原计划。网页中的“可考虑小规模验证”不是项目批准或盈利承诺。

本次源码测试使用可控的模拟模型响应；没有使用真实 API 密钥发起收费请求，也未完成真实 Cloudflare / D1 / R2 / 模型组合的云端验收。

## 1. 使用步骤

先升级数据库到 `0002_ai_analysis.sql`（见 Hermes 文档），部署者配置模型、密钥及费用口径。进入一个项目的 **AI分析**：

1. 点击“业务资料与场景”，补充产品、客户、渠道、售价/成本依据、验证结果、风险与退出安排。可填写最多三个可选场景。保存的是分析资料的版本，不会改原批准计划。
2. 点击“AI授权与费用规则”，阅读实际接收方、模型、最小数据范围、每月调用数及人民币预算；可选择采购提交、阶段开放/关闭批准后自动分析，默认关闭。
3. 在“共同决策”中由全体已加入的合伙人分别同意。少一票不发送，管理员不能代签。筹备期尚未批准基准计划也可以单独确认AI规则。
4. 选择项目/采购/阶段分析。先看本地程序检查和**实际将发送的脱敏输入**，确认费用预占、模型与范围，明确勾选后提交。
5. 分析进入队列；页面仅轮询状态，不会因刷新而重新调用模型。报告就绪后，全体有效项目成员均可查看。
6. 点报告里的来源按钮查看该次冻结资料。风险可记录“补充依据/采取措施/知情接受风险”及理由。建议任务需要人工填写阶段、负责人、不同验收人及截止日期，明确确认后才建立。

“AI已完成”只代表取得并校验了一份结构化响应，不等于风险已排除。风险处置记录也不代替全员会签；本版不把AI结论或处置状态设为新的采购强制通行条件。

## 2. 模型配置（仅服务端）

两种协议已实现。模型ID不写死；部署者应选在其账号可用、支持相应接口且能在本应用调用时限内返回的模型。不要把 ChatGPT 网页订阅当作本应用的 API Key。

| 变量 | 用途 |
|---|---|
| `AI_PROVIDER` | `openai_compatible`（默认）或 `anthropic` |
| `AI_BASE_URL` | 含版本路径的基址，例如 `https://api.openai.com/v1` 或 `https://api.anthropic.com/v1`；不包含最终 `/chat/completions` 或 `/messages` |
| `AI_MODEL` | 真实模型ID；没有默认模型 |
| `AI_API_KEY` | 服务端Secret；不向浏览器返回，不写入Git或配置截图 |
| `AI_INPUT_CENTS_PER_MILLION` | 输入每百万token的**人民币分**，必填正整数 |
| `AI_OUTPUT_CENTS_PER_MILLION` | 输出每百万token的**人民币分**，必填正整数 |
| `AI_OUTPUT_TOKENS` | 默认4096，允许1024–8192 |
| `AI_STRUCTURED_OUTPUT` | 默认启用。明确设置字符串 `false` 可不发结构化输出参数，但本地严格校验不会关闭 |
| `AI_ALLOWED_HOSTS` | 自建/第三方网关的额外允许域名，逗号分隔；只由服务器部署者设置 |

生产密钥以交互式方式配置，不写进命令参数或普通 `vars`：

```bash
npx wrangler secret put AI_API_KEY
```

其他非秘密配置合并进该项目**已有** `wrangler.jsonc` 的 `vars`，保留原APP_URL、D1、R2、路由及名称。本地开发则写入被Git忽略的 `.dev.vars`。配置不完整时页面显示原因，原有业务继续可用。关闭AI不等于不需要执行新增数据库迁移。

第三方接口必须是授权的HTTPS域名，不允许IP/localhost、用户名密码、重定向、查询参数、非443端口。域名允许清单由可信部署者维护，不是一般项目成员可改。允许某域名不代表系统验证了该服务商的隐私政策、DNS安全或业务资质。

OpenAI兼容适配器使用 `/chat/completions`、`max_completion_tokens` 和可选 `response_format.json_schema`；Anthropic适配器使用 `/messages`、`max_tokens` 和可选 `output_config.format`。**不承诺所有“兼容API”都支持这些字段**。有些网关只认 `max_tokens` 或不支持所选模型，应先在测试项目验证；不要通过自动重试或删除本地校验掩盖错误。未实现Gemini原生协议；它只能在部署者另行确认兼容性的网关下使用兼容适配器。

结构化响应的格式约束不保证内容真实。服务端另外检查字段、条数、来源ID、事实性发现的逐字引用和完成状态。引用匹配只说明文字来自输入，不等于资料已经独立核实或推论必然成立。

## 3. 项目授权、暂停和自动触发

模型接收地址、协议、模型ID、费率、输出限额、结构化配置或成员名单变化后，原授权不再满足条件，需要重新全员确认。API Key本身不展示给成员或纳入报告。服务端更换密钥仍须由授权的部署者操作。

任一合伙人可暂停该项目的后续AI发送，不会暂停采购等原业务；恢复必须重新批准AI规则。暂停和资料变更会在排队任务发出前再次核对。**已经发送到服务商的请求无法收回**；过程中暂停或改资料，仍保留最终结果/费用记录并提示报告可能过期。

可选自动触发仅在已批准的项目授权范围内执行：采购单提交成功后，以及阶段开放/关闭的最后一票批准后。自动触发也受输入容量、同项目串行、调用数和费用额度约束。若无法启动则通知触发人，不伪装成“分析通过”，不阻止或替代原来的共同决定。

## 4. 发送范围和来源

采用字段白名单，从**当前项目**生成冻结输入：项目/当前阶段安排、原批准基准、匿名角色分工、任务交付进度、采购数量与报价依据、整数金额/财务摘要、业务补充资料、可选场景及程序检查。

不直接发送用户账户、邮箱、电话、收款账户、付款流水凭证、附件原文件、群Webhook、完整聊天/审计或服务端密钥。采购供应商仅以同项目可关联的摘要标识用于重复采购观察；不要把这种标识理解为不可反推的强匿名保证。

自由文本会进行邮箱、电话、长账号、链接及常见密钥模式的遮盖，但自动脱敏无法识别所有个人信息和商业秘密。**成员仍须看发送预览、控制输入内容**。项目已有成员可以查看共享报告；不要把只读成员当作“看不到AI报告”。

本版没有联网检索、市场数据库、附件OCR或附件全文解析。报价/试销资料是成员提供的描述，不是已核验外部事实。报告固定标明未联网核查；未录入的交易不能解释为没有发生。

输入过大时明确拒绝，不悄悄截断：最多100阶段、200任务、150采购、500笔账目，整个输入不超过80KB。每项目AI运行元数据最多1000条，另受原项目状态容量限制。达到限制后需要容量优化/归档设计，不应直接删除审计或历史报告来腾空间。

## 5. 本地计算和报告内容

本地规则先行检查：预算与可用资金、未核实账目、未经批准的已发生支出、缺失的基准/业务资料、逾期任务、采购关联与有效期等。规则结果与AI解释分开展示；程序原有预算与会签限制仍有效。

场景最多三行，分别填写销量、售价、单位成本、固定费用、期初现金、实际前置付款、其他现金支出和预计回款比例。金额用整数人民币分，比例用万分比（10000表示100%）。计算口径：

```text
收入假设 = 数量 × 售价
成本假设 = 数量 × 单位成本 + 固定费用
利润假设 = 收入假设 - 成本假设
当期回款假设 = floor(收入假设 × 回款比例 / 10000)
期末现金假设 = 期初现金 - 前置付款 - 其他现金支出 + 当期回款假设
保本数量 = ceil(固定费用 / (售价 - 单位成本))，单位差额不为正时为空
```

利润口径与现金付款口径分开：前置付款/其他现金支出由成员独立列明，不能遗漏，也不要把同一付款填两次。此简单情景计算不处理自动税务核算、存货结转、复杂回款曲线；不是会计报表、经营预测或投资收益承诺。

AI报告包含总体意见、来源、发现（输入依据/推断/资料缺失）、需补资料、任务建议、待共同决定事项和局限。总体意见只有“可考虑小规模验证/建议补充资料/存在重大风险/资料不足”，不输出有意编造的成功概率。服务端有限的格式/关键词校验不可能保证每句内容正确，合伙人仍须复核。

## 6. 版本、缓存、导出和费用

输入快照哈希包括对应采购版本、分析提示版本和UTC当天日期。资料变化或跨UTC日期会提示旧报告可能过期；不会覆盖旧报告。仅展示分析日期并不表示做了当天的外部市场调查。

同一项目、相同输入与同一模型配置有成功/排队记录时复用，避免普通重复点击/刷新收费。任何失败或不确定记录仍展示；同输入再次请求须主动确认可能再次计费，没有“悄悄换一份报告”。全体有效成员可查历史、失败原因和每次快照。

每次运行/报告有摘要哈希并关联到项目审计记录；SQLite/D1触发器限制业务层更新或删除原始输入与报告。此设计不是外部不可篡改存证，数据库/服务器最高权限仍需单独控制。

每项目按**UTC自然月**限制1–300次及最多10000元估算预算。排队任务即预占次数和费用；发送前取消释放，服务商已收到或是否收到不确定的失败不自动退占用。概览中的次数包含有效排队预占，不应称为全部已完成调用。

费用需要部署者按真实服务商报价填写。计价单位是“人民币分/百万token”；例如服务商确认为每百万token人民币5元时填500（仅单位说明，不是推荐或真实报价）。美元报价应另行换算、留存当时汇率及费率依据，不是软件自动更新。

发送前用请求字节和输出上限保守预估；完成后对普通usage用配置费率计算估算值。缺usage、特殊缓存计费、超时或未知结果保留预占并标未知。不自动获取账单，也不保证预占覆盖所有服务商特殊费用。**应用限额不等于服务商硬消费上限**，应同时在实际API账号设置预算、限流及告警。已在途的调用不可撤回；实际估算超过预占时如实记账并阻止后续额度不足的申请。

项目JSON导出中的 `aiManifest` 是完整AI资料索引及哈希，不重复内嵌大快照。下载每个报告的JSON可获得快照与报告；完整运维备份需导出D1（含ai_jobs/ai_reports）并单独备份R2。JSON文件可能含商业敏感资料，不能上传公开Git。

## 7. 队列、失败和排障

同项目只允许一个AI任务排队/运行，避免并发消费和重复分析。外部请求时限20秒，运行租约60秒。优先利用请求后的 `waitUntil` 处理；现有每10分钟Cron回收超时租约，并每次取一个排队AI任务。通知Queues不承担AI任务，v1.1无需新建Queue。

较慢模型、首次结构化编译或大型资料可能超过20秒。此时显示“不确定/超时”，不显示“无风险”。用户应先查服务商请求/账单，调整模型或资料后明确决定是否重试。此轻量任务实现面向少量合伙项目，不保证跨项目大规模任务及时完成；需要吞吐量升级时再引入持久工作流，不应延长waitUntil后声称已解决。

| 状态 | 含义 |
|---|---|
| queued | 已冻结输入并预占额度，待发送 |
| running | 已取得处理租约，可能已发送 |
| completed | 响应完成、格式与来源校验通过，可查看，但不保证判断真实 |
| failed | HTTP错误或响应校验失败，没有有效报告 |
| uncertain | 超时/进程中断/未知结果；服务商可能已收费，没有有效报告 |
| cancelled | 发送前资料、成员或授权变化，未发送，释放预占 |

模型未配置：检查变量、真实正费率及密钥，不能关闭预算检查或用0费率“先跑起来”。403：项目或角色权限不符。409：预览/授权过期、幂等冲突或已有失败需确认。429：项目预算/次数、同项目排队或用户请求限流。500/503及挂起任务：检查数据库迁移与绑定，但不要把包含商业输入的原始响应或Key打印进公共日志。

## 8. 上线验收

使用独立测试项目和明确授权的API费用额度。至少验证两种选用协议之一的真实请求、usage口径、首次延迟、项目全员授权、暂停/成员变更、实际Cron恢复、模拟失败、不同成员登录及手机从预览到报告的在线全流程。没有这些实测，不把本地测试当成已上线/已验证经营效果。完整已测与未测清单见 `ACCEPTANCE_AI.md`。
