# 通用 AI 分析与轻量支出 · v1.4.0

正式部署仍为 **Cloudflare Workers + D1 + 私有 R2**。三个入口：项目合理性、支出／采购、阶段复盘。AI没有会签票，不修改预算、计划、账目，不发起付款。

本版去掉了配置中的 token 单价、人民币分析预算和可见输出 token 上限。保留实际调用次数、服务商返回的用量和内部安全保护，**不是免费调用或无限生成**。真实金额以服务商账单为准。

## 1. 项目情况：一段话即可

创建项目填写名称、计划预算和项目说明；说明可以留空后补。项目内的「AI分析 → 项目情况与分析重点」只包含一段说明和可选关注点。例如：

> 我们三人合作做AI漫剧，先完成两分钟样片。我负责资金和选题，其他人负责画面与剪辑。先核对制作耗时和返工成本，再决定是否批量制作。

不强制客户、销售、商品、供应商或库存。中视频推广、账号运营、软件开发、非盈利合作和探索项目都使用同一入口。已有计划、任务、支出自动带入；没有客户不自动列为缺失或风险。

只修改分析资料版本，不改原批准计划。旧版已有业务字段、客户说明、场景假设仍保留并参与相关分析；本次只更新两个字段不会把它们清空。「经营场景测算（可选）」独立保留，不适用时不用填写。没有描述时报告可指出资料不足，不阻止保存项目。

## 2. 小额简单记录，大额再分析

在「AI授权与金额分级」设定超过多少元自动分析。**500元只是默认建议阈值，可调整；等于或低于阈值的普通支出不自动调用AI，超过才触发。**分类为生活采购不豁免大额；任何金额都能由合伙人手动发起分析。

自动分析需要项目已生效的全员AI授权、勾选采购提交触发、模型可用及调用额度充足。它在采购提交成功后排队，不在保存草稿、刷新页面时调用。授权提议默认勾选采购金额分级、默认不勾选阶段自动复盘；未全员通过之前都不会因此启用。

关联累计检查也可触发：

- 填写相同「同一事项名称」的有效申请，跨日期/阶段累计；适合分批及同一服务承诺。
- 未明确关联时，检查当前项目近7天、同一阶段、相同供应商加用途，或相同标题的记录。
- 只计待会签、已批准、已下单、已验收记录；撤销、拒绝、草稿不计。同单不重复计入，不跨项目。

若自身小额但相关累计超过阈值，会提示「核对是否同一事项」，并按已授权设置分析。规则是线索，可能有误报，不是证明违规，也不能保证识别所有拆单。超预算等原规则在提交前阻止业务，不能用AI同意绕过。

金额按**本次已经承诺的完整总额**：年付订阅/明确分期包括全部期数，不只首付款；按月可随时停止且没有未来付款承诺的服务如实填写当期，不虚构全年债务。规则依赖如实录入，系统不能从简短说明自动识别所有合同责任。

### 快速支出申请

入口「支出与会签 → 快速支出申请」。四项主要输入：买什么／付什么、承诺总额、简单用途、商家／收款对象。阶段、日期、费用分类、执行人与不同验收人提供建议值，展开后可核对修改；报价、风险、退款说明、附件可选。建议值不是替成员批准，提交会签前必须核对。

API额度、云服务、软件订阅、推广、外包、设备、生活采购都可使用；它生成原采购流程的真实草稿，一行总额数量为1。复杂采购保留「多项明细申请」，修订不会把多项清单自动压成一项。

**小额免AI ≠ 免记账、免通知、免收款核对或免会签。**所有原有阶段预算、全员确认、独立复核、版本变更与审计规则继续执行。未填风险显示未补充，不写成无风险。

## 3. 管理员模型配置

系统管理 → AI模型配置：URL、Model、API Key为主要配置，另有启停、协议选择、第三方域名确认与操作原因。密钥只在服务器加密保存，留空保留，不回显；清除须关闭，不退回旧环境密钥。配置变更和测试连接仍要求本人密码及已有MFA验证。

保存不调用模型；测试连接独立确认可能计费，仅用通用测试句。项目成员没有密钥配置权，但可查看实际接收方、模型及授权范围。

无网页配置的部署仍可使用以下服务端配置：

| 项目 | 含义 |
|---|---|
| AI_PROVIDER | openai_compatible 或 anthropic |
| AI_BASE_URL | 获授权HTTPS基址，包含版本路径（如 /v1），不包含最终接口路径 |
| AI_MODEL | 该账号真实可用的模型ID |
| AI_API_KEY | Secret；不要写入公开代码、页面或普通vars |
| AI_ALLOWED_HOSTS | 第三方网关允许主机，兼容原部署方式 |

旧 AI_INPUT_CENTS_PER_MILLION / AI_OUTPUT_CENTS_PER_MILLION 不再作为启用条件或计价依据，可以不用填写。旧配置与报告留存，不会因升级丢失Key。

两种适配器保持 `/chat/completions`（max_completion_tokens）和 `/messages`（max_tokens）。不承诺所有标注“兼容”的网关支持相同参数。内部仍保留输出保护和结构化设置；特殊网关可由部署者设置 AI_STRUCTURED_OUTPUT=false，最终JSON/引用校验仍不关闭；AI_OUTPUT_TOKENS为可选部署层保护参数，默认8192，支持1024–32768，不能超过实际模型能力。网页不再要求用户选择这些数值。没有自动联网读取所有模型能力或价格。

## 4. 提示词内置，不用自己编写

后端 `src/ai-prompts.js` 包含共同核心和三类任务提示词，版本为 `cooperation-review-1.4.0`。管理员可点「内置分析提示词」只读查看；另有可选「补充分析偏好」，不能修改核心代码或赋予AI审批权。补充内容不能填秘密。

核心关注目标、当前进展、时间和资金投入、分工、验证及暂停条件，按项目自然语言选择相关角度。有收入目标才检查收入路径；没有收入目标则不强行算盈利。来源内的指令、项目说明和补充偏好都当作数据，不能覆盖安全规则。

默认精简：先看判断、最多3个关键问题及下一步。标准和详细模式可展开，但不要求凑字数，缺失资料最多3项。后端验证JSON字段、已有来源ID、事实性引用、未联网标记和报告容量；引用存在不证明输入真实，提示词也不保证模型没有幻觉。重要决定仍由合伙人复核。

## 5. 截断补齐、调用记录和限制

没有可见的输出字符限额，但并非无限生成。一次请求限时20秒；响应/组合报告保留字节容量保护。模型明确以 `length` 或 `max_tokens` 停止时，保存已取得片段并最多排队补齐一次：

1. 首次请求前预占最多2次调用；月额度只剩1次时仅允许1次。
2. 第二次不从头重写整份报告，携带原片段要求补齐剩余JSON。
3. 下次后台调度领取，重新检查授权、成员、配置和资料；刷新只读取状态，不新建分析。现有每10分钟Cron会处理队列，跨项目任务也可能排队，不保证立即补齐。
4. 拼接后重新校验结构和来源，合格才发布；两次仍不完整则失败，不把半份报告当作无风险。
5. 普通HTTP错误、拒绝、超时、费用未知不会自动重发；用户确认后可手动重试并计新的调用。

相同项目、相同输入和配置的成功/排队任务复用；同项目串行，原子领取和幂等保护继续生效。中途暂停、修改资料、跨UTC日期等使快照不匹配时，不再发送后续片段，已发生的请求和用量仍保留。已发出的内容不能收回。

按UTC自然月限制1–300次调用。页面区分实际尝试、未发送预占、成功报告、失败、不确定及已返回用量。一次报告可有2次调用；未知usage不视为0成本。旧历史无明确尝试元数据按原一次调用保守处理，旧报价记录不覆盖；新版本兼容字段 reserveCents/chargeCents 的0只是废弃字段占位，**绝不是免费账单**。

应用调用额度不是服务商硬金额上限，管理员连接测试也不归属某项目额度。仍需在真实API账户设预算和告警并核对账单。

## 6. 隐私、版本和部署

继续只发送当前项目的白名单数据和脱敏文本，不直接发送账号、邮箱、手机号、收款账户、原附件、付款凭证、Webhook或密钥。不联网调查市场或平台，不自动OCR。自动脱敏不保证移除所有商业秘密，手动预览应核查，自动模式需先共同授权数据范围。

新提示词/配置指纹/授权版本变化后，原v1授权不静默放宽：需各项目重新全员确认v2规则。归档、停用账号、成员退出或AI暂停依然会拦截发送。历史报告、签名、审计保留，核心业务不依赖AI授权是否更新。

必须先增量迁移 `0005_lightweight_ai.sql` 再部署；不要清库、改写旧迁移、重建管理员或更换配置根密钥。本版备份新快照schemaVersion为5，并继续接受v1.3的版本4数据恢复校验；真实灾备仍须独立资源验收。

完整操作与升级见 `HERMES_DEPLOY.md`，实际测试范围见 `ACCEPTANCE_V1_4.md`。本次本地SQLite/离线浏览器及模拟模型结果不证明真实Workers或API兼容、模型判断质量、账单或手机真机已经验收。
