# 系统管理后台 · v1.3.0

入口：登录后，左侧导航底部 **系统管理**；手机先打开左上角菜单。只有数据库中当前仍有效的系统管理员能看到入口并访问 `/api/admin/*`。即使没有加入任何项目，管理员也可以使用后台。

## 1. 两层权限，不混为一谈

| 身份 | 可以做什么 | 不因此获得什么 |
|---|---|---|
| 系统管理员 | 管理全站用户、项目生命周期、只读审阅/导出、AI连接设置及管理日志 | 不能以管理员接口给采购投票、付款、改账或代签 |
| 项目合伙人 | 查看本人项目资料，按既有规则共同决策 | 无全站用户、其他项目、模型密钥管理权限 |
| 项目执行成员 | 执行分配给自己的任务和已批准采购 | 无合伙人会签票 |
| 项目只读成员 | 查看自己参与项目的资料和AI报告 | 无写入与审批权 |

系统管理员可以跨项目只读审阅业务记录、下载项目内已登记的私有附件、读取AI历史报告。上述访问会记入管理员日志；普通项目接口仍要求本人是该项目成员。管理员身份与项目身份是两套字段，系统角色调整不会自动增删项目合伙人。

管理员及部署者属于高度受信任角色。重置他人密码、掌握服务器/数据库权限本身具有高权限风险，软件无法证明登录者一定是账号对应的自然人，也不能防御恶意最高权限者。账号变更有记录和站内提醒，但不等同于实名电子签名、独立审计或第三方存证。

## 2. 管理页面（原五项与新增运维入口）

### 管理总览

展示用户数量、有效管理员和停用账号、正常/归档/回收站项目数量、AI任务和通知投递状态，以及数据库、R2、配置加密密钥、可选队列的绑定状态。这里只检查可读取数据/绑定存在，不表示真实云端、短信或模型已经验收。

### 项目与回收站

可搜索、分页、按状态筛选，查看未完成采购/任务、待审批、待核实账目及已登记应收应付。可以只读审阅、导出业务JSON、调整项目角色，以及操作生命周期：

```text
正常项目 ─归档→ 归档只读 ─取消归档→ 正常项目
正常/归档 ─删除到回收站→ 回收站 ─恢复→ 归档只读
```

归档与删除都要求再次验证管理员密码，准确输入项目名称、确认未完成事项影响、填写原因，并校验项目版本。项目有未完成任务或付款责任时显示提醒，但管理员仍能明确选择归档/移入回收站；这不代表责任已消失。

归档保留成员的查看和导出能力，拒绝新业务写入、接受邀请、AI新发送及外发通知。回收站不出现在普通成员项目列表，直接访问也会被阻止；管理员仍可查看、导出和恢复。恢复先回到归档，不直接恢复采购操作。已有模型/消息请求一旦发出无法追回，其结果和费用仍需记录。

**删除是可恢复的逻辑删除，不是物理清库。** 采购版本、账目、原签名、审计和附件均保留，不能借删除项目擦除历史责任。没有“清空回收站/彻底抹掉账目”入口。附件原文件以及完整AI报告须分别下载或做D1/R2运维备份；项目JSON不能替代完整备份。

### 用户与权限

支持新建用户、设置登录用户名、编辑显示姓名、设置系统管理员/普通用户、控制能否新建项目、启用/停用账号、查看所属项目、重置临时密码和撤销所有会话。

新建或重置用户需要管理员输入临时密码（12–128字符），本人首次登录必须改密。已有密码只保存散列，不提供查询明文功能。密码、权限或停用状态变化会撤销旧登录；不能停用或降级自己，数据库还会阻止删除/停用最后一位有效管理员。编辑自己的系统资料会撤销当前会话，需重新登录。

当前邮箱用于账号与邀请绑定，不在后台直接改写；管理员可设置用户名用于登录。姓名更新不回写已冻结的项目成员/历史签名快照。没有删除用户的入口，用停用保留责任记录。

重置密码、撤销会话和修改账号权限，会向该用户所属的非回收站项目的成员写入站内提醒；不发送密码，不自动发短信或邮件。停用不会取消这个人的必签资格，因此可能阻塞在办会签；应先处理人员交接，而不是悄悄删除反对者。

### 项目内角色调整

从项目卡片点击“成员权限”。筹备期、且没有待处理共同决策时，可以调整角色，最终合作基准仍须全员确认。正式项目只产生 `member_role` 提议，原全体合伙人明确同意才生效；任何人反对都不会被系统删掉必签资格。

项目创建人保留合伙人身份；至少保留两位合伙人。合伙人转为非合伙人前，先按原流程共同调整分配比例为零。拟改为只读的成员若还有未完成的执行/验收工作，必须先交接。角色生效后，未下单采购重新核对会签，旧AI成员授权也失效。没有代理签名或单人强行放行。

### AI模型配置

支持 `Key / Model / API URL`、协议（OpenAI兼容或Anthropic）、真实输入/输出费率、输出限额、结构化参数开关及全站启停。

管理员填写新的Key时以 `CONFIG_ENCRYPTION_KEY` 做AES-GCM加密后保存在D1；已有Key不回显，留空保留，清除必须同时关闭AI。关闭或清除之后不会退回旧环境变量密钥。部署者仍需提前提供服务端32字节配置加密根密钥，该根密钥不能在网页中任意重置，否则原企业微信/AI配置将无法解密。

原环境变量配置可继续使用。第一次后台保存时可以保留并加密迁入原Key；之后后台记录优先。管理员不应将Key填入URL、模型名、操作原因或截图中。一般成员没有配置入口，但仍能看到自己项目的实际模型接收方、模型和费用口径，以便知情确认外部发送。

填写基址而非最终接口路径，例如带版本前缀的 `/v1`，不要把 `/chat/completions` 或 `/messages` 一起填写。只接受HTTPS、指定或明确确认的主机、无URL密码/查询参数/重定向，不允许IP、localhost或内网域名。第三方主机必须由管理员明确确认，允许名单不等于对服务商隐私、DNS或资质的背书。

费率界面单位是“元/百万token”，保存时转为整数人民币分。请自行核实真实报价；软件不会自动获取价格或汇率。保存**不调用模型**，但会产生新的配置版本，使原项目授权失效；需由各项目合伙人重新确认。Key轮换也会改变版本，避免静默更换接收账号。

“测试连接”是独立操作：再验密码、勾选可能计费、每小时全站最多5次，仅发送通用测试句，不含项目资料、不请求工具。10秒超时、128输出token上限，不自动重试，不返回服务商原始正文。只验证基础鉴权/文本响应，不验证正式结构化分析质量；测试费用不归入某个项目额度，需核对服务商账单，应用限额不是服务商硬消费上限。

### 管理员日志

只追加记录用户管理、项目状态/角色变更、只读审阅、导出、附件下载、AI配置和测试，以及账号改密。日志含操作者、对象、原因及必要差异，不存密码或Key。日志只对系统管理员开放；重要成员账号变化另发项目站内提醒。

## 3. 默认管理员与升级

- 新空站点可显式设置 `INITIAL_ADMIN_ENABLED=true` 和 Secret `INITIAL_ADMIN_PASSWORD`。用户名固定初始化为 `admin`，初始显示名为系统管理员，邮箱默认 `admin@local.invalid`，可以通过 `INITIAL_ADMIN_EMAIL` 在初始化前指定真实管理员邮箱。
- 用户指定的初始密码只通过Secret注入，不写入Git、SQL、文档示例或共享默认值。此初始化允许10–128字符的临时密码；正常新密码仍须12–128字符，首次登录强制修改，未改前不能读取任何业务/管理接口。
- 没有明确启用和Secret就不会生成公开默认账号，仍可通过原BOOTSTRAP_TOKEN初始化页面建立管理员。
- 从v1.1.2及更早版本升级，迁移只把 `settings.bootstrapped` 记录的原始初始化账号升级为系统管理员并增加用户名 `admin`。**原密码不变**，不重复建账号、不重置密码、不覆盖项目。原邮箱登录继续可用。
- 如果旧库缺少可靠的初始化记录，不自动猜测“第一个用户”是谁；由可信部署者核实备份和归属，不能靠注册抢管理员。
- 初始化完成后建议删除部署中的 `INITIAL_ADMIN_PASSWORD` 和不再需要的 `BOOTSTRAP_TOKEN` Secret；重启/重新部署不会覆盖既有密码。

## 4. 安全升级

先备份D1、私有R2和配置密钥，并核实恢复方案。保留真实域名、绑定、Secrets与本地改动，获取本仓库最新版。新增迁移是 `0003_administration.sql`；从1.0升级同时应用未执行的0002，使用Wrangler迁移跟踪，不手工重复执行ALTER脚本。先迁移再部署。

禁止直接回滚为不识别归档/停用状态的旧代码：旧版可能忽略新的安全限制。发生问题应停用外部入口/进入维护，保留新数据，修复并前向部署；恢复备份前必须核对后续真实业务，不能静默丢弃。

本地Node适配器现已记录 `local_migrations`，重复启动不重复ALTER、不重置旧数据；正式D1仍由Wrangler维护其迁移记录。

## 5. v1.3 已实现的运维与交接

原后续清单中的管理员第二因素、自动加密备份和恢复演练、全站通知服务商及负责人移交/退出清算已经实现。后台新增“二次验证、备份与恢复、通知服务商、投递与告警”；项目内新增“移交与退出”。完整入口、权限、额度、配置与故障边界见 `OPERATIONS_V1_3.md`。

管理员第二因素采用TOTP与恢复码，并非Passkey；全站强制默认关闭。备份不是只导出JSON，包含数据库与已登记附件，支持独立恢复验证，但没有生产覆盖/自动灾备切换和自动删除留存。通知支持现有企业微信、阿里云协议，不是任意服务商市场。

本版仍未实现：Passkey、自动跨账户副本与保留期删除、完整生产灾备切换、自定义细粒度权限、登录设备列表、复杂库存估值和退出法律/税务自动核算。不能把这些写为已上线能力。

从v1.2升级先备份，执行 `0004_operations_security.sql`，保留现有账户与根密钥。新版本实际测试见 `ACCEPTANCE_V1_3.md`；以前的 `ACCEPTANCE_ADMIN.md` 为v1.2历史报告。
