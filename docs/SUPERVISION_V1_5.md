# 出资人监督与合作执行 · v1.5.0

正式部署仍为 Cloudflare Workers + D1 + 私有 R2。本次围绕“出资方不盯日常细节，但按时知道成果、偏差和新增投入”补齐六项流程，不更改现有账号密码、MFA、AI Key存储方式或AI配置免重复验证的行为。

## 一、先从这里开始

升级后进入一个合作项目，默认打开 **出资人总览**。原来的项目总览仍在导航中，名称改为“业务总览”。其他新入口是“简短汇报与成果”“追加投入”“计划变更”“异常处理”。电脑、手机使用同一网站和账号。

先点击总览中的 **监督规则**：选择实际执行方为汇报负责人，选择另一位合伙人作为阶段验收/异常复核人，确定多久汇报、多久对账、什么情况下升级提醒。建议先使用每7天汇报、每14天核实资金、3天处理宽限的示例设置；这些只是表单建议值，不会自动给真实项目生效。

规则提交后在“共同决策”由全体已加入合伙人分别确认。少一个人不生效，管理员不能代签。旧项目不因代码升级被直接设置新期限或冻结业务。停用或改变监督规则，也须重新共同决定。

执行方在日常批准范围内自主工作；出资方固定查看简短汇报，并在阶段结束、追加投入、改变方向或明显异常时参与决定。网站不能阻止线下银行卡或其他渠道绕过审批付款，实际资金释放与付款复核仍须对应系统中的有效批准。

## 二、出资人总览

首页集中显示当前开放阶段、目标、验收标准、截止日期、最新成果、本人待处理事项和偏差线索。

资金分别显示：已登记现金支出、已承诺未付、可用于新安排的资金、待复核账目。已登记支出包含返还和分配等现金流出，不等于经营亏损；未核实流入不增加可采购现金，追加出资承诺也不计入到账。

同时显示最近汇报提交时间、进展覆盖至哪一天、最近真实资金对账时间。没有汇报或进展覆盖日期过旧时，明确标记“资料待核实”。补交一个月前的汇报不会伪装成最近一周的进展。即便有新汇报，也只显示“已报告、仍须核实”，不宣称一切正常。

进入项目页面会重新获取服务器资料，避免一直看到其他成员操作前的旧状态。总览另有刷新按钮。没有浏览器自动后台监控或实时银行同步；长期不查看系统仍可能错过尚未处理的决定。

## 三、简短汇报与成果

执行方主要填写：完成了什么、成果或原因在哪里、有什么问题/偏差、下一步和需要大家决定的事情。没有进展也可以如实说明，不要求客户、销售、供应商或完整商业计划书。

阶段、汇报周期和指定复核人提供建议值；可关联本项目已上传附件，以及要复盘的一笔追加投入。大视频不直接上传到当前凭证接口，可在成果说明中填写已约定的工程或素材位置。附件仍受原有文件类型和大小限制。

提交时自动冻结当前任务、采购承诺、期间收支、账目编号和资金摘要。后续资金变化不会改写原汇报的快照。更正需要提交新版本，旧版本、原已阅情况和验收意见保留。

**确认已阅不是批准。** 各有效成员可以记录自己看过某一具体版本，不能借阅读同意修改计划、追加投资或关闭阶段。汇报中提出的新想法，仍需另行提交变更或追加投入申请。

每份阶段成果有一位不同于提交人的合伙人验收。只允许处理最新的阶段成果版本；负责人不能自己验收。退回需说明原因，修改后以新版本再提交。认可成果后阶段仍保持开放，不能绕过原全员阶段会签。

## 四、计划变更：先看新旧对比，再共同确认

可以申请修改：

| 对象 | 可修改的范围 |
|---|---|
| 项目 | 项目具体情况、方向和范围说明 |
| 未完成阶段 | 名称、目标、验收标准、开始及截止日期 |
| 未完成任务 | 名称、说明、交付成果和关键期限 |

表单展示原批准安排，保存拟调整内容、原因与资金/时间/范围影响。共同决策页面再次显示逐项对比。只有全员同意才应用新版本，原始合作基准不覆盖。会签期间相关计划变化，最后一票会要求重新核对，不使用过期方案。

具体技术方法或日常操作在既定范围内由执行方决定，不必每个小动作提交变更。预算重新分配、人员/比例变化仍使用原共同决策；不能通过计划变更提交隐藏字段直接修改角色、预算或执行状态。

确实需要提前启动下一阶段时，可针对未开放阶段提出明确的“提前开放例外”，说明前一阶段尚未完成验证及相应风险。全员批准例外后，还需另行批准阶段开放。例外绑定计划版本并只能使用一次；前阶段不会因此被标为完成。更改预算、计划或成员后，过期例外不能继续使用。

## 五、阶段成果、验收与后续投入

在已共同启用“阶段成果前置验收”的项目中：

```text
执行方提交阶段成果
→ 指定另一位合伙人核实并验收
→ 全体合伙人确认阶段关闭
→ 申请开放下一阶段
→ 全体确认后，才开放相应阶段采购
```

提交成果后，任务、账目、采购、成员或阶段标准发生有关变化，原验收不再作为当前完整依据。系统会在独立验收及阶段会签最后一票重新检查，必要时要求更新成果。已完成的阶段或任务不能被新表单直接改写。

“阶段预算”“项目总预算”“真实已核实资金”继续分开管理。开放阶段不等于自动转账；银行付款权限、账户余额和其他线下承诺仍需共同核实。

## 六、追加投入：三个状态严格区分

```text
项目愿意增加预算 ≠ 某个人已经确认承担 ≠ 实际资金已经到账
```

追加单包括前一轮结果、未完成事项、此次用途、增加金额、每人拟承担金额及性质、验证目标、停止条件、复盘日期。用途区分“完成原约定”“新增试验”“扩大规模”“新方向”，避免全部混成模糊的测试费。已有账目与近期汇报自动冻结，不重复抄写。

所有分担之和必须等于追加总额。承担金额的合伙人在原有同意按钮之后还须明确勾选本人的金额；只对项目点同意不能代替个人承诺。非承担者仍参与项目决策，但不出现虚假的个人承担确认。

全员通过后，只增加项目和目标阶段的批准预算并留下出资承诺；**不新建虚假来款、不自动改变分配比例**。分配比例确实需要变动时另行共同确认。监督规则已启用的项目，原预算变更入口不能直接提高总预算绕过追加说明；仍可在总预算不增加的情况下进行共同调整。

实际来款可以分次登记，再由登记人之外的合伙人复核。已有单独登记的正向出资/借款流水可以关联到追加单，不重复增加现金。超出剩余分担的来款不能强塞入本单；应另记真实事实并共同处理。反向更正保留追加关联，降低对应完成金额，不会把已冲销的来款继续当作已足额出资。

追加单到了复盘日期，资金未足额核实与验证结果未汇报会分别提醒。汇报可关联该笔追加，并如实写失败或尚未验证；提交复盘不意味着验证成功、不批准下一轮，也不自动解除已经建立的异常处理单。

没有任何关联实际来款的追加单可以再经全员同意撤销，并扣回尚未被占用的追加预算。已经关联实际款项，即使后续有更正，也不能通过简单撤销擦除事实。尚未完成个人投入承诺的成员不能悄悄退出或被降权跳过责任。

## 七、异常处理与提醒

规则检查包括：逾期汇报、延期任务/阶段、久未对账、未经事前批准的支出、阶段成果久未验收、追加资金未核实或到期未复盘。未录入的线下事实不能凭空识别；规则线索不自动认定违约或赔偿。

未启用监督规则时，界面仍能展示已有资料中的线索，并允许合伙人手工建立处理单。规则全员生效后，现有Worker Cron分批检查项目、为新线索建立异常单、发送站内提醒，并对逾期未关闭/久未确认阅读的事项升级提醒。

每个异常指定处理人和不同的合伙人复核人：

```text
待处理 → 原因与处理安排 → 实际处理结果 → 独立复核关闭／退回
```

没有先说明原因和处理办法，不能直接提交“已处理”。处理人不能自己关闭。规则来源仍存在时，不能声称已消除；需要继续处理，或者由复核人明确记录知情处理/误报及依据。原支出或延期事实不删除。对同一稳定来源不重复无限建单；新的期限或不同异常仍会形成新记录。

限制新增投入只有在事先共同启用相应规则后生效：重要异常未复核关闭，以及可选的严重缺报。普通延期默认提醒处理，不一刀切停止项目。限制期间仍可登记已有订单实际付款、真实账目、汇报和异常处理结果，不能因为暂停就隐藏责任。

外部微信/短信继续使用原项目接收范围、服务商设置和本人短信同意。没有渠道配置不会宣称通知已送达；已发通知不等于已阅或问题解决。通知、管理员通知测试和告警出口改为明确的manual重定向模式，拒绝跟随3xx，也不自动重发重定向请求。没有改变原凭据存储或验证规则。

本版本定时每轮最多检查3个项目，每个项目最多新建8个异常，按游标推进，升级摘要按日去重。受实际Cron、配额、网络及渠道限制，不承诺精确到秒即时通知；总览在读取时仍会给出最新规则线索。此模块不额外调用AI。

## 八、升级、容量与边界

本版没有新增SQL表或列。新增资料保存在现有项目JSON中，包含在项目导出、原D1备份和恢复校验中；业务表schemaVersion仍为5。从已执行0001–0005的版本升级无需新增数据库迁移。更旧站点仍须按迁移记录应用原来缺失的迁移，不直接重复执行ALTER脚本。

保留真实配置、域名、绑定、Secrets、账号密码、原始签名、历史AI报告和本地未提交修改。新监督限制必须全体重新确认，不能让升级代替真实同意。不要清库或用仓库占位配置覆盖线上配置。

单项目仍受原1.4MB状态容量限制；本模块另有240份汇报、400个异常、100笔追加单、200次计划变更的保护上限，可能先达到总体字节上限。上限不是建议使用量，更不是无限保存；接近时应安排导出、完整备份和后续项目分期，不删除历史腾空间。正式大规模使用前需专项容量设计。

本版不是银行资金控制、独立审计、自动赔偿裁决或合同解除系统。停止条件中的自由文本由成员结合真实情况判断；代码不会假装已经理解并自动执行所有自然语言约定。保存成果位置也不等于已检验内容质量。实际线上资源、通知回执、手机设备和合伙人流程仍须按验收清单核对。
